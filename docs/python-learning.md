# Python 学习辅助规则

用户对 Python 还不熟悉。写 Python 代码时，Codex 应该默认把代码当成学习材料来写，但不能为了教学破坏工程质量。

## 注释原则

新增以下用法时，要在代码中加简短注释说明它解决什么工程问题：

- 函数。
- 类。
- 装饰器。
- 类型注解。
- 上下文管理器。
- 异常处理。
- `dataclass`。
- Pydantic model。
- 生成器。
- 异步代码。

注释优先解释“为什么这样写”和“这个语法在工程里的作用”，不要只重复代码字面意思。

## 难点讲解

如果某个 Python 用法对初学者偏难，先用一个 5-15 行的小例子解释，再放回 Parenting Copilot 的真实代码里。

必要时让用户亲手写一个小实验，例如：

- 打印变量。
- 构造一个 `dict`。
- 定义一个 `dataclass`。
- 捕获一次异常。

## 用户亲手编码练习

在学习任务的费曼复述之后，优先安排一个代表性小编码题。题目默认采用“一个小函数 + 2 个测试样例”的形式，让用户练习把 Agent 概念落到代码里。

题目要围绕 Parenting Copilot 的真实模块职责，例如判断上下文是否足够、选择意图路由、包装结构化输出、生成澄清问题或处理安全降级。前两次练习 Codex 应提供函数名、输入输出结构、样例输入和期望输出；用户主要完成函数体和测试样例。

## 工程边界

代码仍然要保持可维护：

- 不为了教学写过度注释。
- 不为了讲语法改动已经验证过的逻辑。
- 教学注释应随着用户熟悉程度逐步减少。
- 每次改动后优先运行 `py_compile`、payload-only 路径或对应测试。

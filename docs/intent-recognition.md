# 意图识别与协作模式

本文件列出用户在学习过程中常用的表达方式，以及 Codex 应该进入的协作模式。目标是减少反复解释，让用户可以直接用触发词控制学习节奏。

## 触发词总览

触发词保持短句化。用户可以先查看这张表，再选择合适说法；长句可以作为自然表达，但文档中优先记录短触发词。

| 触发词                | 进入的模式  | Codex 响应                              |
| ------------------ | ------ | ------------------------------------- |
| `领取任务`             | 标准学习任务 | 找到当前任务，定义目标，按学习流程推进                   |
| `当前阶段`             | 学习状态查询 | 查看清单、日志和产物，说明当前阶段、已完成内容、卡点和下一步        |
| `评估一下：...`         | 学习评估   | 评估用户的理解、方案偏好、学习流程想法或学习效果              |
| `只讲概念`             | 概念模式   | 只讲心智模型、工程意义和产品连接，不写代码                 |
| `解释代码`             | 代码解释   | 解释模块职责、关键语法和设计原因，必要时用 Android/Java 类比 |
| `添加生词：...`         | 生词收集   | 将概念作为待整理内容处理，不直接归入稳定知识库               |
| `我来复述`             | 费曼复述   | 检查用户自己的解释，指出缺口，帮助修正理解                 |
| `记录一下`             | 复盘沉淀   | 提炼本轮讨论，准备写入学习日志、笔记或周复盘                |
| `开始` / `执行` / `写入` | 执行模式   | 说明会改哪些文件，然后小步修改、运行和验证                 |

## 1. 学习启动类

| 意图 | 用户说法示例 | Codex 应该做什么 | 默认是否写入 |
| --- | --- | --- | --- |
| 领取当前任务 | `领取任务`，也可说 `今天领取 CHECKLIST 里的下一个任务，带我完成` | 读取 `CHECKLIST.md` 和当天学习日志，找到下一个合适任务 | 否 |
| 获取当前学习阶段 | `当前阶段`，也可说 `当前阶段是什么？` | 说明当前阶段、最近完成内容、未完成验收项、推荐下一步 | 否 |
| 定义今日目标 | `帮我把这个任务定义清楚` | 改写为 `今日目标`、`完成标准`、`最小产物`、`验收方式`、`复盘问题` | 用户确认后可写 |

## 2. 学习理解类

| 意图          | 用户说法示例              | Codex 应该做什么                           | 默认是否写入   |
| ----------- | ------------------- | ------------------------------------- | -------- |
| 概念解释        | `只讲概念`，也可说 `今天只讲概念` | 先建立心智模型，再连接工程实现和 Parenting Copilot 场景 | 否        |
| 代码解释        | `解释代码`，也可说 `解释这段代码` | 先讲模块责任，再讲关键语法、数据流和设计原因                | 否        |
| Python 语法补课 | `这个语法是什么意思？`        | 说明用途、风险、最小示例；对特殊用法标明为什么需要它            | 否        |
| 添加生词        | `添加生词：Protocol`     | 先作为 Inbox 内容收集，后续理解、分类、确认后再沉淀         | 需要明确写入   |
| 费曼复述        | `我来复述`，也可说 `我来复述一下` | 检查用户解释是否覆盖问题、机制、边界和应用场景               | 用户确认后可记录 |

## 3. 学习评估类

统一触发词：

```text
评估一下：...
```

这个触发词覆盖四类评估：理解评估、方案评估、学习流程评估、学习效果评估。也可以说 `帮我评估一下：...`。

| 意图 | 用户说法示例 | Codex 应该做什么 | 默认是否写入 |
| --- | --- | --- | --- |
| 评估我的理解 | `评估一下：我理解 Agent Loop 就是观察、判断、行动` | 分出正确部分、模糊部分和错误部分，给出更准确表述 | 否 |
| 评估方案偏好 | `评估一下：我觉得先学 Memory 比 Tool Calling 更重要` | 说明优点、风险、隐含成本，并给 1-3 个成熟做法对照 | 否 |
| 评估学习流程 | `评估一下：这个任务我想只做概念，不写代码` | 判断是否适合当前阶段，给出推荐学习节奏 | 否 |
| 评估学习效果 | `评估一下：我现在是否真正掌握了这个任务` | 按掌握标准检查学习效果，指出未完成的验收项 | 否 |

学习效果评估默认按 5 个问题检查：

1. 用户能否说明它解决什么问题。
2. 用户能否讲出核心机制。
3. 用户能否看懂或修改最小代码。
4. 用户能否解释 Parenting Copilot 里怎么用。
5. 用户能否说出一个失败场景或边界。

## 4. 执行沉淀类

| 意图 | 用户说法示例 | Codex 应该做什么 | 默认是否写入 |
| --- | --- | --- | --- |
| 开始实现 | `开始` / `执行` / `按你的建议做` | 先说明修改范围，再执行最小实现和验证 | 是 |
| 写入文档 | `写入` / `按这个更新` | 将已确认内容写入对应文档、日志或复盘 | 是 |
| 记录复盘 | `记录一下` | 提炼本轮讨论，不保存原始聊天；写入前说明目标文件 | 需要确认位置 |
| 更新清单状态 | `这个任务可以标记完成` | 对照任务完成标准检查；缺少费曼复述或复盘时不能勾选完成 | 通过验收后可写 |
| 代码实验 | `做个最小实验` | 设计最小可运行代码，运行验证，解释输出 | 需要执行确认 |
| Debug / 诊断 | `这个报错怎么回事？` | 复现、定位、解释根因；需要改代码时先说明修改范围 | 视情况 |
| Review | `帮我 review` | 以代码审查视角列出 bug、风险、缺少的测试和开放问题 | 否 |

## 协作原则

- 默认先讨论、先澄清、先定义目标。
- 只有明确进入执行模式时，才修改文件、运行实现或更新任务状态。
- 当 Codex 不确定用户真实意图时，先用 1 个简短问题确认，再执行或写入。例如用户说“精简触发词”时，应先确认是“减少触发词数量”还是“把触发词缩短”。
- `评估一下：...` 是主要评估入口，不额外扩散更多评估触发词。
- 学习效果不能只靠感觉判断，必须对照产物、验收、费曼复述和复盘。
- 临时生词、想法和理解先进入收集区，经过理解和确认后再沉淀为稳定笔记。

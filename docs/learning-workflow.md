# 学习流程

本文件承接 `AGENTS.md` 中的每日学习流程细节。`AGENTS.md` 只保留最高优先级规则；当任务进入学习执行时，再读取本文件。

## 每次学习如何开始

推荐用户直接说：

```text
领取任务
```

完整说法也可以是：

```text
今天领取 CHECKLIST 里的下一个任务，带我完成。
```

如果用户想指定节奏，可以说：

```text
只讲概念
今天偏工程实现，少讲一点概念。
今天用 Android 架构师能理解的方式讲。
```

## 意图不确定时的澄清规则

当 Codex 不确定用户真实意思时，先问 1 个简短澄清问题，再执行或写入。尤其是用户在调整学习流程、触发词、文档结构或验收标准时，不要把模糊表达直接当成确定需求。

例子：

```text
用户：触发词需要精简。
Codex：这里的“精简”是指减少触发词数量，还是把每个触发词缩短？
```

## 目标定义规则

每次开始学习前，先把任务从“我要学什么”改写为“今天完成后我能做到什么”。

格式：

```text
今日目标：
完成标准：
最小产物：
验收方式：
复盘问题：
```

例子：

```text
今日目标：理解结构化输出为什么是 Agent 工程的基础。
完成标准：能解释普通聊天输出和 JSON schema 输出的区别。
最小产物：一个 parenting_advisor.py。
验收方式：输入一个亲子教育问题，输出稳定 JSON。
复盘问题：结构化输出如何降低 Agent 的不可控性？
```

## 知识定位规则

定义目标之后、正式讲概念或写代码之前，先用“问题驱动的 Agent 知识定位法”定位当前知识点。

每个知识点先回答 5 个问题：

```text
1. 它解决了什么问题？为什么这样解决？
2. 它在 Agent 里属于哪一层？
3. 它依赖前面哪些知识？后面哪些能力会用到它？
4. 它在 Parenting Copilot 产品中承担什么职责？
5. 它和我已有知识体系怎么连接？
```

第 1 个问题最重要，可以拆成：

```text
问题是什么：
不用它会怎样：
为什么这个方案有效：
```

这些问题的答案要沉淀到对应概念笔记中；每日学习日志只记录当天最关键的理解、卡点和决策。方法论本身见 [问题驱动的 Agent 知识定位法](../notes/学习方法/问题驱动的%20Agent%20知识定位法.md)。

## 业务到代码阅读规则

当学习任务进入“理解业务和看代码实现”阶段时，先用一个真实 Parenting Copilot 案例写一张“业务到代码阅读卡”，再读代码。

固定顺序：

```text
真实案例
  -> 业务预期
  -> Agent 流程
  -> 模块边界
  -> 关键函数
  -> 数据结构
  -> 测试样例
  -> 失败路径
```

阅读时优先追踪一条链路，不从文件顶部逐行硬读。Python 语法、类型标注、`dataclass`、`Enum`、`Protocol` 等细节，放在链路清楚后再解释。

方法论本身见 [业务到代码阅读卡](../notes/学习方法/业务到代码阅读卡.md)。配套地图见 [业务到代码阅读地图](assets/learning-maps/business-to-code-reading-map.svg)。

## 费曼后的代表性小编码题

当用户完成费曼复述后，不直接进入写入、复盘或标记完成。先给一个代表性小编码题，用来验证用户能否把概念迁移到代码表达。

推荐版规则：

```text
费曼复述
  -> 代表性小编码题
  -> 用户写一个小函数
  -> 用户补 2 个测试样例
  -> Codex 做代码反馈
  -> 再决定是否写入笔记、复盘或更新 CHECKLIST
```

小编码题应满足：

- 来自一个真实 Parenting Copilot 业务场景。
- 只训练一个 Agent 模块职责，例如路由、上下文充分性、结构化输出校验、澄清问题生成或安全降级。
- 题目足够小，通常 10-20 分钟可以完成。
- 前两次练习由 Codex 提供函数名、输入输出结构、输入样例和期望输出；用户只补核心逻辑。
- 要求用户写 2 个测试样例：一个正常路径，一个边界或失败路径。
- 不要求一次实现完整 Agent Loop、真实 LLM 调用、数据库、UI 或复杂框架。

Codex 反馈时优先看三件事：函数职责是否单一，数据结构是否能被 Agent Loop 使用，测试样例是否覆盖关键行为。Python 语法问题只在影响理解或正确性时展开讲。

## 学习评估与定稿规则

当用户在学习过程中提出方案偏好、个人理解、学习流程调整或学习效果评估请求时，不直接判断为“采用”或“拒绝”，先按下面顺序讨论：

1. 客观评价：说明这个想法解决了什么问题、适合在哪里、可能带来什么成本或混乱。
2. 成熟方案对照：列出 1-3 个已有的成熟做法、行业常见模式或可学习对象。
3. 推荐方案：结合当前项目阶段、用户学习目标和 Parenting Copilot 主线，给出一个推荐选择。
4. 用户选择：用户确认哪个方案适合自己后，再定稿。
5. 执行写入：只有用户明确说“开始”“执行”“写入”“按这个更新”“按你的建议做”等执行词后，才修改文件。

默认优先推荐简单、可持续、低维护成本的方案。只有当一个流程重复 3-5 次并且边界稳定后，才考虑抽象成更正式的模板、目录规范或 Codex Skill。

主要评估触发词：

```text
评估一下：...
```

它覆盖理解评估、方案评估、学习流程评估和学习效果评估。也可以说 `帮我评估一下：...`。完整意图对照表见 [intent-recognition.md](intent-recognition.md)。

## 每次学习的 8 步

1. 读取 `CHECKLIST.md`，找到当前任务。
2. 使用 `define-goal` 思路，把任务改写成可验收目标。
3. 用知识定位卡片说明：它解决什么问题、在 Agent 中的位置、上下游关系、产品职责和个人知识连接。
4. 如果需要读代码，先用业务到代码阅读卡追踪一条真实案例链路。
5. 询问或确认学习模式：概念优先、代码优先、架构优先、复盘优先。
6. 用 10-20 分钟讲清楚核心概念。
7. 结合 Parenting Copilot 解释这个概念的产品价值。
8. 带着完成一个最小代码或文档产物。
9. 用户完成费曼复述后，给一个代表性小编码题，让用户写一个小函数和 2 个测试样例。
10. 做验收：运行代码、检查输出或审查设计。
11. 更新清单、Obsidian 笔记和周复盘。

如果当天任务偏大，优先保证：

- 用户真的理解核心概念。
- 有一个最小可运行或可审查产物。
- 明确记录当天卡点。

## 每天推荐节奏

默认 3 小时节奏：

```text
30 分钟：概念讲解
90 分钟：动手实现
30 分钟：测试、调试或审查
30 分钟：复盘与笔记
```

轻量模式：

```text
20 分钟：概念
40 分钟：小实验
20 分钟：复盘
```

深挖模式：

```text
30 分钟：概念
90 分钟：实现
40 分钟：扩展实验
20 分钟：架构复盘
```

## 什么时候可以做成 Codex Skill

当某个流程重复 3-5 次，并且形式稳定后，可以考虑抽成 skill。

优先候选：

- 每日领取任务流程。
- 学习任务复盘流程。
- Agent 架构审查流程。
- Prompt 设计审查流程。
- Evaluation 测试集生成流程。
- Obsidian 学习笔记生成流程。

当前计划：

- 已安装官方 `define-goal` skill，用于目标定义。
- 已安装自定义 `discussion-first-learning` skill，用于先讨论再执行。
- 未来可以创建 `agent-learning-coach` skill，把每日学习方法、Obsidian 笔记、复盘和验收规则合并成一个稳定学习流程。

抽成 skill 前，先在 `skills-candidates/` 中记录流程。

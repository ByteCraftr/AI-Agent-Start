# 业务到代码阅读卡

这是一种用于理解 Parenting Copilot 代码的阅读方法。它解决的问题是：不要从文件顶部开始硬读代码，而是先拿一个真实业务案例，判断它在产品中应该怎么走，再沿着这条业务链路追到模块、函数和数据结构。

它和 [[问题驱动的 Agent 知识定位法]] 的关系：

- 知识定位法回答“这个知识点为什么存在、在 Agent 里处于哪里”。
- 业务到代码阅读卡回答“一个真实输入如何经过这些模块变成系统行为”。

## 核心原则

每次读代码前，先写清楚 5 件事：

```text
1. 案例是什么？
2. 用户真正的问题是什么？
3. 产品上应该如何处理？
4. Agent 链路应该经过哪些步骤？
5. 每一步落在哪个模块、函数和数据结构？
```

这样读代码时，关注点就从“这个文件每一行是什么意思”变成“这条业务链路在代码中如何被实现”。

## 阅读顺序

推荐固定顺序：

```text
真实案例
  -> 业务预期
  -> Agent 流程
  -> 模块边界
  -> 关键函数
  -> 数据结构
  -> 测试样例
  -> 失败路径
```

不要反过来从语法开始读。Python 语法、类型标注、dataclass、Enum、Protocol 等写法，应该在链路已经清楚后再解释。

## 示例：孩子考试前焦虑

```text
案例：
孩子考试前很焦虑，晚上一直说自己肯定考不好。

用户输入：
孩子考试前很焦虑，晚上一直说自己肯定考不好。

业务预期：
1. 先识别这是情绪问题，不是普通学习方法问题。
2. 不能直接给完整建议，因为缺少年龄、持续时间、家长目标等背景。
3. 应该先追问少量关键信息，而不是假设孩子情况。

Agent 链路：
observe: 接收用户输入。
reason: Intent Router 判断 intent=emotion；Context Checker 判断信息不足。
act: 选择 ask_clarifying_question。
persist: 记录本次 route、context_check、action 和 response。

模块映射：
业务动作 | 代码位置 | 责任 | 我应该看什么
接收输入 | parenting_agent.py | Agent Loop | ParentingAgent.run
判断问题类型 | intent_router.py | Router | IntentRouter.classify, Intent.EMOTION
判断信息是否足够 | context_sufficiency.py | Context Checker | ContextSufficiencyChecker.check
选择下一步 | parenting_agent.py | Orchestration | _choose_action
生成当前响应 | parenting_agent.py | Minimal response | _build_response
记录运行过程 | parenting_agent.py | Trace/Persist | AgentRunRecord, run_history

关键数据结构：
1. RouteResult：Router 的输出合同，说明 intent、confidence、reason、safety_priority。
2. ContextSufficiencyResult：上下文检查合同，说明 next_step、missing_slots、clarifying_question。
3. AgentRunRecord：一次 Agent run 的追踪记录。

关键函数：
1. IntentRouter.classify：决定“去哪条流程”。
2. ContextSufficiencyChecker.check：决定“信息够不够”。
3. ParentingAgent.run：把 observe -> reason -> act -> persist 串起来。

失败路径：
1. 如果出现自伤、不想活、严重霸凌等信号，应该进入 safety_response。
2. 如果缺少关键背景，应该追问，而不是生成建议。

暂时不用理解：
1. 真实 LLM 调用。
2. 长期记忆系统。
3. Tool Calling。
4. RAG 和引用。

我自己的复述：
这条输入不是先让模型回答，而是先经过 Agent Core 的几个确定性判断。Router 判断它属于情绪流程，Context Checker 判断背景不足，Agent Loop 决定当前动作是追问，并记录这次运行结果。
```

## Android 架构类比

- `ParentingAgent.run` 类似 UseCase / Interactor 的主执行入口。
- `IntentRouter.classify` 类似业务路由器，只决定进入哪个处理流程。
- `ContextSufficiencyChecker.check` 类似 request/context 前置条件校验。
- `RouteResult`、`ContextSufficiencyResult`、`AgentRunRecord` 类似稳定 DTO / Result contract。
- `EVALUATION_CASES` 类似用例级测试样例，也是业务说明书。

## 使用时机

- 读一个新模块前。
- 学一个新 Agent 概念后。
- 代码能运行但业务链路不清楚时。
- 准备复盘或费曼复述前。

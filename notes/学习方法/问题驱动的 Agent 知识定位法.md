# 问题驱动的 Agent 知识定位法

这是一种用于学习 AI Agent 工程的方法。它的重点不是先记住一个知识点的名字，而是先理解它为什么存在、解决什么问题、如何进入系统结构，以及如何连接到已有经验。

## 核心原则

每个 Agent 知识点都先回答 5 个问题：

```text
1. 它解决了什么问题？为什么这样解决？
2. 它在 Agent 里属于哪一层？
3. 它依赖前面哪些知识？后面哪些能力会用到它？
4. 它在 Parenting Copilot 产品中承担什么职责？
5. 它和我已有知识体系怎么连接？
```

第 1 个问题最重要，可以进一步拆成：

```text
问题是什么：
不用它会怎样：
为什么这个方案有效：
```

## 为什么这样学

Agent 工程不是孤立知识点的堆叠，而是一套系统能力。只按任务推进，容易出现几个问题：

- 知道概念名，但不知道它解决什么系统问题。
- 能写出局部代码，但不知道它处在 Agent 哪条链路。
- 学完一个点后，不知道它和 Router、Prompt、Memory、Tool、Evaluation、Safety 的关系。
- 新知识没有接到自己已有的 Android、架构、产品经验上，难以长期记住和迁移。

这个方法用“问题 -> 位置 -> 关系 -> 产品职责 -> 个人类比”的顺序，帮助每个知识点进入稳定知识网络。

## 相关学习理论

这个方法结合了几种学习思路：

- 问题驱动学习：Problem-Based Learning。先从真实问题出发，再寻找需要的概念和工具。
- 系统思维：Systems Thinking。把每个知识点放回 Agent 系统，看它和其他模块如何互相影响。
- 知识图谱式学习：Knowledge Mapping。记录知识点之间的上下游关系，避免形成孤立笔记。
- 迁移学习：把 Android 架构经验迁移到 Agent 架构。用已有的软件工程经验理解新领域。
- 费曼学习法：最后用自己的话复述关系。通过解释“它解决什么问题、为什么这样解决、和其他知识怎么连接”来检查理解是否稳固。

## 每次学习如何使用

领取任务后，先写一张知识定位卡片：

```text
当前知识点：

1. 它解决了什么问题？为什么这样解决？
问题是什么：
不用它会怎样：
为什么这个方案有效：

2. 它在 Agent 里属于哪一层？

3. 它依赖前面哪些知识？后面哪些能力会用到它？
上游依赖：
下游影响：

4. 它在 Parenting Copilot 产品中承担什么职责？

5. 它和我已有知识体系怎么连接？
```

然后再进入概念讲解、工程设计、最小实验和验收。

## 答案要不要记录

要记录，但不要全部写进同一个地方。

- 方法论笔记记录“以后怎么学”。
- 每个概念笔记记录该知识点的 5 个问题答案。
- 每日学习日志记录当天讨论出来的关键理解、卡点和决策。
- 周复盘记录重复出现的问题、学习方式调整和下一步改进。

也就是说，5 个问题的答案应该主要写入对应概念笔记，例如 `Intent Router`、`澄清问题`、`Agent Loop`，而不是长期堆在这篇方法论笔记里。

## 示例：信息充分性判断与追问

```text
当前知识点：信息充分性判断与追问

1. 它解决了什么问题？为什么这样解决？
问题是什么：家长的问题经常缺少年龄、场景、持续时间、家长目标等关键信息。
不用它会怎样：Agent 会凭空补全背景，给出看似合理但不可靠的建议。
为什么这个方案有效：先定义必要信息槽位，缺什么问什么；只有信息足够时才进入建议生成。

2. 它在 Agent 里属于哪一层？
Agent Core，处在 Router 之后、Advice Generation 之前。

3. 它依赖前面哪些知识？后面哪些能力会用到它？
上游依赖：Intent Router、结构化输出、安全边界。
下游影响：Agent Loop、Memory、Tool Calling、Evaluation。

4. 它在 Parenting Copilot 产品中承担什么职责？
让产品表现得像一个谨慎的亲子教育助手：先理解家庭场景，再给建议。

5. 它和我已有知识体系怎么连接？
类似 Android UseCase 执行业务逻辑前，先校验 request/context 是否满足前置条件。
```

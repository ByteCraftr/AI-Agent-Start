## 讨论沉淀

核心结论：

```text
Prompt 负责提高模型遵守合同的概率；
Validation 负责判断合同是否真的被遵守；
Retry/Repair 负责有限恢复；
Fallback 负责在恢复失败时保护系统。
```

今天采用的边界原则：

```text
代码只修包装问题，不猜业务内容。
```

可以自动修复的情况：

- markdown ```json 代码块包裹。
- JSON 前后的解释性文字。
- JSON 字符串前后空白。

不应该自动猜的情况：

- 缺失 `risk_level`。
- 非法风险等级或建议类别。
- 空的 `professional_boundary`。
- 高风险内容被写成低风险。

修复失败后的安全降级：

- 不返回半残的 `ParentingAdvice`。
- 不保存长期记忆。
- 不调用后续工具。
- 不进入正式建议卡片。
- 给家长一段保守的 fallback 文案，引导补充年龄、持续时间、具体场景和风险信号。
- 如果存在自伤、暴力、被欺负或紧急危险，优先建议联系紧急服务、学校老师、医生或心理健康专业人士。

## 关键理解

LLM 是不稳定上游。可靠 Agent 不能把模型输出直接交给 UI、记忆、评估或安全模块，而要先经过 parse、validate、有限 repair 和 fallback。

## 卡点

已完成费曼复述。后续需要继续注意：LLM repair 之后仍然必须再次 parse 和 validate，不能因为“修复过”就直接信任。

费曼复述：

```text
llm 是概率的内容输出，不能百分之百保证输出的内容的可靠性。所以在agent 端需要通过代码来保证可靠性，先parse ，后验证。容错机制不能少，如果只是简单的格式错误，可以代码修复，如果比较严重的错误，也可以重试或者错误加返回的内容，让llm 修复后再返回，但是这种方式是有限制的次数，如果不行，就进入 fallback，友好提示。
```

## 决策

W2-T3 的最小实验先不用真实 API，也不引入 Pydantic；重点放在可靠性控制流和边界判断。

- 创建 `labs/w03-agent-core/context_sufficiency.py`。
- 实现 `RequiredSlot`、`NextStep`、`SlotCheckResult`、`ContextSufficiencyResult`、`ContextSufficiencyChecker`。
- 支持第一轮信息不足追问、第二轮从 `existing_context` 补齐状态、信息充分后放行、高风险信号优先安全响应。

## 关键理解

Slot filling 定义 Agent 缺什么；多轮状态记录已经补齐什么；追问策略决定下一句怎么补，而且一次不应该问太多。

补充理解：

- `slot filling` 不是收集越多越好，而是把会影响建议方向的关键信息拆成固定槽位。
- 多轮状态解决“用户不会一次把信息说完整”的问题，避免第二轮重复追问已经补齐的信息。
- 追问策略要控制问题数量，优先问最影响建议方向的信息，降低用户负担。
- 可靠 Agent 遇到模糊问题不能急着回答，因为缺少年龄、持续时间、场景和家长目标时，建议容易变得泛泛、错位，甚至忽略风险；先追问是为了让后续建议更具体、更安全。

## 费曼复述

用户复述：

```text
1. 填信息，关键信息槽位。尽量补足完整的用户问题信息。
2. 解决用户问题信息完整性。
3. 有可能遗漏问题信息，减少输入，让用户没有负担。
4. 问题信息不完整，肯定不是用户想要的，体验不好。
```

校正：

```text
slot filling 更准确地说是补齐会影响建议方向的关键信息，不是追求完整收集所有用户信息。
多轮状态不是泛泛地解决“完整性”，而是让 Agent 记住前面已经补齐的槽位。
追问策略的重点是一次只问少量高价值问题，避免把用户当成填表。
模糊问题不能直接回答的核心风险是建议会泛泛、错位，甚至漏掉风险信号。
```

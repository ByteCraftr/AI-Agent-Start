## 讨论沉淀

核心结论：

```text
Prompt 负责提高模型遵守合同的概率；
Validation 负责判断合同是否真的被遵守；
Retry/Repair 负责有限恢复；
Fallback 负责在恢复失败时保护系统。
```

今天采用的边界原则：

```text
代码只修包装问题，不猜业务内容。
```

可以自动修复的情况：

- markdown ```json 代码块包裹。
- JSON 前后的解释性文字。
- JSON 字符串前后空白。

不应该自动猜的情况：

- 缺失 `risk_level`。
- 非法风险等级或建议类别。
- 空的 `professional_boundary`。
- 高风险内容被写成低风险。

修复失败后的安全降级：

- 不返回半残的 `ParentingAdvice`。
- 不保存长期记忆。
- 不调用后续工具。
- 不进入正式建议卡片。
- 给家长一段保守的 fallback 文案，引导补充年龄、持续时间、具体场景和风险信号。
- 如果存在自伤、暴力、被欺负或紧急危险，优先建议联系紧急服务、学校老师、医生或心理健康专业人士。

## 关键理解

LLM 是不稳定上游。可靠 Agent 不能把模型输出直接交给 UI、记忆、评估或安全模块，而要先经过 parse、validate、有限 repair 和 fallback。

## 卡点

已完成费曼复述。后续需要继续注意：LLM repair 之后仍然必须再次 parse 和 validate，不能因为“修复过”就直接信任。

费曼复述：

```text
llm 是概率的内容输出，不能百分之百保证输出的内容的可靠性。所以在agent 端需要通过代码来保证可靠性，先parse ，后验证。容错机制不能少，如果只是简单的格式错误，可以代码修复，如果比较严重的错误，也可以重试或者错误加返回的内容，让llm 修复后再返回，但是这种方式是有限制的次数，如果不行，就进入 fallback，友好提示。
```

## 决策

W2-T3 的最小实验先不用真实 API，也不引入 Pydantic；重点放在可靠性控制流和边界判断。

- 用 10 个亲子教育样例验证学习、情绪、亲子沟通、行为习惯、学校关系、高风险分类。
- 发现并修正一次优先级问题：`考试 + 焦虑` 最初被学习规则截走，调整为情绪信号优先于普通学习信号。

## 关键理解

Router 决定“去哪儿”，Handler 决定“怎么处理”，Agent Loop 决定“按什么顺序运行”。高风险和情绪信号的优先级不能随便排，否则普通流程会吞掉需要特殊处理的问题。

## 费曼复述

用户复述：

```text
意图路由，先判断该问题是什么意图，先通过不同的意图，配置不同的执行流程，解决不同的问题情况。是有针对性的。这样效果会更好。Handler 执行的链路，根据不同的意图，执行不同的链路。Agent Loop 主进程，统一入口
```

校正：

```text
Handler 更准确地说不是“链路本身”，而是某条链路里的具体处理器。
Agent Loop 才是统一入口和主编排流程。
```

# 澄清问题

## 它解决了什么问题

用户向 Parenting Copilot 提问时，经常不会一次说完整上下文。例如“孩子不爱写作业怎么办？”缺少孩子年龄、持续时间、具体场景和家长目标。

如果 Agent 在信息不足时直接生成建议，回答容易变得泛泛、错位，甚至忽略高风险信号。澄清问题的价值是：在正式建议前，先补齐会改变建议方向的关键信息。

## 它在 Agent 里的位置

澄清问题属于 Agent Core 中的上下文充分性判断，位于 Intent Router 之后、建议生成之前。

```text
user input
  -> Intent Router：判断去哪条流程
  -> Context Sufficiency：判断信息够不够
  -> Ask Clarifying Question / Generate Advice / Safety Response
```

W3-T1 的 Router 负责决定“去哪儿”。W3-T2 的信息充分性判断负责决定“现在能不能安全地进入建议生成”。

## 核心概念

### Slot filling

`slot filling` 是把会影响建议方向的信息拆成固定槽位，并判断每个槽位是否已经具备。

Parenting Copilot 当前最小实验使用 4 个槽位：

- `child_age`：孩子年龄或年级。
- `duration`：问题持续多久或发生频率。
- `situation`：具体发生场景。
- `parent_goal`：家长希望先改变什么。

它不是保存完整聊天记录，也不是越多越好。它只关心下一步决策需要哪些关键字段。

### 多轮状态

多轮状态记录上一轮已经补齐的信息。第一轮用户没有说完整时，Agent 可以先追问；第二轮用户补充后，系统要把已有槽位和新输入合并判断，避免重复问同一个问题。

### 追问策略

追问策略决定下一句话怎么问。当前原则是一次最多问两个问题，优先问最影响建议方向的信息。

这样做的原因：

- 降低用户输入负担。
- 避免把对话变成表单。
- 先补最关键的信息，让后续建议更具体。

### 安全优先

高风险信号不能被普通 slot filling 拖住。如果输入包含自伤、轻生、严重暴力、严重霸凌或紧急危险，应直接进入 `safety_response`，而不是继续追问年龄、场景等普通信息。

## Parenting Copilot 场景

同一句“孩子不爱写作业怎么办？”，不同上下文会导致完全不同的建议：

- 6 岁刚入学，重点可能是习惯建立和任务拆分。
- 10 岁持续半年，可能需要看学习压力、亲子互动和执行功能。
- 最近两天不写作业，可能只是短期情绪或环境变化。
- 每天拖到深夜且亲子冲突严重，建议需要包含节奏调整和冲突降温。

所以可靠 Agent 不应该看到模糊问题就立刻回答。先追问不是拖慢体验，而是保护建议质量和安全边界。

## 当前实验产物

关键输出合同：

- `ContextSufficiencyResult.is_sufficient`
- `ContextSufficiencyResult.next_step`
- `ContextSufficiencyResult.missing_slots`
- `ContextSufficiencyResult.clarifying_question`

`next_step` 只有三种：

- `ask_clarifying_question`
- `generate_advice`
- `safety_response`

## 费曼复述

我的理解：

```text
slot filling 是补齐会影响建议方向的关键信息槽位；
多轮状态让 Agent 记住前面已经补齐的信息，不要重复追问；
追问策略要一次只问少量高价值问题，降低用户负担；
可靠 Agent 遇到模糊问题不能急着回答，因为缺少年龄、持续时间、场景和家长目标时，建议容易泛泛、错位，甚至忽略风险。
```

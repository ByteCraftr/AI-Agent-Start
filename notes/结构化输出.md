# 结构化输出

## 它解决什么问题

结构化输出把 LLM 的自然语言回答变成可被代码校验、解析和传递的稳定结构。对 [[Parenting Copilot]] 来说，这不是格式美化，而是 Agent 和业务系统之间的输出契约。

如果没有结构化输出，UI、安全策略、评估脚本和后续 Agent Loop 都只能猜模型说了什么；有了结构化输出，代码可以明确拒绝缺字段、错类型、非法枚举值或不完整 JSON。

## 核心模型

本次实验定义了三个核心结构：

- `ParentingAdvice`：一次亲子教育建议的结构化 DTO。
- `RiskLevel`：风险等级枚举，包括 `low`、`medium`、`high`、`emergency`。
- `AdviceCategory`：建议类别枚举，包括学习、情绪、沟通、行为、学校关系和安全。

当前实现位于：

```text
labs/w02-structured-output/parenting_advice_schema.py
```

## 三层理解

概念层：结构化输出解决的是“模型输出不可控、系统无法可靠消费”的问题。

工程层：先定义数据结构和枚举，再把模型输出的 dict 校验成 `ParentingAdvice`。只有校验通过的对象才能进入后续流程。

产品层：Parenting Copilot 不能只输出一段看似温和的话，还要明确风险等级、建议类别、原因、行动步骤、沟通话术和专业边界。

## Python 学习点

- `Enum` 用来限制字段只能取固定值，避免模型随意创造类别。
- `dataclass(frozen=True)` 让结构化结果更像稳定 DTO，创建后不随意修改。
- `TypeVar("EnumT", bound=Enum)` 表示泛型类型变量，限定它只能代表 `Enum` 或其子类。
- `type[EnumT]` 表示传入的是枚举类本身，例如 `RiskLevel`，不是枚举值。
- `enum_type(raw_value)` 会调用枚举类，把字符串转换成枚举值；非法值会抛出 `ValueError`。

## LLM 如何知道这个结构

`ParentingAdvice` 本身不会自动传给 LLM。工程上需要把结构转换成模型能理解的输出要求：

```text
ParentingAdvice 代码模型
  -> JSON Schema
  -> prompt 或 API structured output 参数
  -> LLM 生成 JSON
  -> 本地代码再次校验
```

W2-T2 会继续拆分 prompt 职责：`system prompt` 管角色和安全边界，`task prompt` 管当前问题，`format prompt` 管输出结构。

## Streaming 与校验

Streaming 主要改善等待体验，不负责提升结构可靠性。

合理流程是：

```text
stream chunks
  -> UI preview path：边接收边显示，标记为生成中
  -> validation path：累积完整 buffer，结束后 JSON parse + schema validate
```

可以边流式显示草稿，但不能在校验完成前保存记忆、调用工具、标记风险等级或进入正式建议卡片。

## 输出失败、修复与降级

W2-T3 增加的是“合同违约处理机制”：

```text
LLM 原始输出
  -> parse：能不能解析成 JSON
  -> validate：是否符合 ParentingAdvice 合同
  -> repair：能不能修复包装问题
  -> fallback：不能修复时返回可理解错误
```

关键边界：

```text
代码只修包装问题，不猜业务内容。
```

可以自动修复的是 markdown 代码块、JSON 前后解释文字、前后空白这类包装问题。不应该自动猜的是缺失 `risk_level`、非法 `category`、空的 `professional_boundary` 等业务判断问题。

对 Parenting Copilot 来说，业务字段错误可能影响风险判断、安全边界、记忆和评估，所以不能用默认值把错误藏起来。

修复失败后的安全降级不是把错误吞掉，而是让系统回到保守状态：

- 不返回半残的 `ParentingAdvice`。
- 不保存长期记忆。
- 不调用工具或进入后续 Agent Loop。
- 不把这次结果标记成成功回答。
- 给家长明确说明“这次没有生成可靠的结构化建议”，并提示补充年龄、持续时间、具体场景和风险信号。
- 如果存在自伤、暴力、被欺负或紧急危险，优先联系紧急服务、学校老师、医生或心理健康专业人士。

当前实验位于：

```text
labs/w02-structured-output/output_repair.py
```

## 费曼复述

已经学习到：在 Python 中枚举的使用、`TypeVar` 的使用、LLM 里的输入和输出格式的重要性，以及校验的必要性。

用架构语言表达：结构化输出让 Agent 的回答从“模型生成的一段文本”变成“系统可验证的合同对象”。这样后续模块不用猜文本含义，而是依赖明确字段和校验结果。
